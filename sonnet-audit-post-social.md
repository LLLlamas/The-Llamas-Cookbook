# Sonnet Audit (post-social, 2026-04-30)

Generated by claude-sonnet-4-6. Most findings now fixed.

## Closed

- `CloudKitFriendship.approveFriendRequest` / `deleteFriendship` `currentUserID` is non-optional (auth bypass closed).
- `CloudKitRecipeImport.deleteAllRecipeImports` split into two single-field queries; no longer depends on a compound-OR index.
- `FriendRecipeDetailView.performImport` sets `isImporting = true` unconditionally up front (closes double-tap window).
- `writeImportAuditRow` extracts `String?` values before `Task.detached` (no `@Model` capture across the boundary).
- `LibraryView` profile button is `.disabled(editor.active != nil)` (no silent broken UX while the editor sheet is up).
- `CloudKitSubscriptions.writeRecipeImport` exhaustion path logs via `Logger`.
- `ImportCountCache` lives in UserDefaults; mutating the cache no longer triggers `LibraryMirrorService.enqueueUpsert`.
- `AttributionSheet` comment about `pendingFriendOpenID` reflects "deferred, not added."

## Still open

- `UserProfile` records are world-queryable on the public DB; add a CloudKit Console Security Role to gate query access to registered users. Revisit before adding sensitive fields.
- `FriendsStore.refresh()` fetches each friend's `UserProfile` serially. Move to `withTaskGroup` capped at ~10 concurrent.
- Consider server-side uniqueness or pre-write existence check for `Friendship(userA,userB)` (client dedupe is best-effort across two devices or a force-killed mid-send).

## Cross-surface note

Display-name denormalization is inconsistent: `RecipeImportRecord` carries `importerDisplayName`; `Friendship` and `PublishedRecipeSummary` do not. `FriendLibraryView` therefore needs a full `UserProfileSnapshot` to push.
